# 兵符 · Godot 版

象棋卡牌对战《兵符》的 Godot 实现。

**当前状态：可以开局对着打了** —— 有棋盘、有棋子、有手牌、能部署 / 装备 / 移动 / 吃子 / 断桥 / 结束回合，一路能打到分出胜负。
锦囊**只实现了 2 种**（增援、断桥），其余 12 种等流程稳定后再补。

规则以 `../象棋卡牌-规则书-v0.5.md` 为准；设计理由见 `../象棋卡牌-设计笔记.md`。

## 怎么跑

Godot 版本：**4.7.2**（Steam 版）。已装好，路径写在 `run.bat` 顶部。

```bat
cd C:\Users\sl\Documents\桌游想法\兵符-godot

run.bat            :: 开游戏
run.bat edit       :: 打开 Godot 编辑器
run.bat all        :: 跑全部测试（引擎 167 + 界面 52 + 护栏 74 + 自对弈 3）
run.bat test       :: 只跑引擎测试
run.bat ui         :: 只跑界面冒烟测试
run.bat guard      :: 只跑架构护栏（三条铁律 + 视图几何 + 文字居中）
run.bat selfplay   :: 只跑 AI 自对弈（验证一局打得完）
run.bat shot       :: 渲两张图验收界面（会闪一个窗口）
```

不想用脚本的话，直接在 PowerShell 里敲（**已验证可用**）：

```powershell
cd 'C:\Users\sl\Documents\桌游想法\兵符-godot'
$godot = 'D:\Game\steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe'
& $godot --headless --path . --script res://tests/TestRunner.gd
& $godot --headless --path . --script res://tests/UiSmoke.gd
& $godot --headless --path . --script res://tests/ArchGuard.gd
& $godot --headless --path . --script res://tests/SelfPlay.gd

# 改过界面布局之后，跑这个看一眼（会开窗口）：
& $godot --path . --script res://tests/Screenshot.gd
```

退出码 **0 = 全绿**、**1 = 有失败**，可以直接接进 CI。

> **为什么不给 .ps1 脚本**：你这台机器的 PowerShell 执行策略禁止运行 `.ps1` 文件。
> 改用 `.bat`，但 cmd.exe 有两个坑已经踩过了，都写在 `run.bat` 的注释里：
> ① **必须 CRLF 换行**（LF-only 的 .bat 会被 cmd 解析成乱码）；② **`%~dp0` 结尾的反斜杠必须去掉**，否则 `"%PROJ%"` 的收尾引号会被 `\"` 转义掉，把后面的参数全吞进同一个参数。
> 另外 **Godot 在 `--path` 无效时会返回 0**，所以 `run.bat` 额外检查了 `project.godot` 是否存在，避免"假绿灯"。

## 目录

```
engine/          纯逻辑引擎，绝不 extends Node
  Rules.gd       棋盘几何与常量（坐标、九宫、桥、河界、人口表）
  Piece.gd       一个棋子（纯数据）
  MoveGen.gd     走法生成（七种棋子 + 桥 + 象堵桥 + 每回合一次）
  Game.gd        对局状态与动作（开局 / 部署 / 装备 / 移动 / 解散 / 回合 / 持续效果 / 锦囊）

scenes/          界面层，唯一允许碰 Node 的地方
  Palette.gd     水墨配色 + 字体 —— 全项目唯一的色值来源
  Main.tscn      主场景
  Main.gd        布局、把手势翻译成 do_* 调用
  BoardView.gd   画棋盘与棋子，把点击翻译成 (列,行)

tests/
  TestRunner.gd  引擎测试（167 条断言，自带极简断言，不依赖插件）
  UiSmoke.gd     界面冒烟测试（52 条，含点击链路 / 终局锁定 / 死路预警 / 排版不重叠）
  ArchGuard.gd   架构护栏（74 条，正则 + 反射，盯着那三条铁律 + 视图几何 + 文字居中）
  SelfPlay.gd    AI 自对弈（3 条，跑 6 颗种子，验证一局真能打完）
  Screenshot.gd  截图工具（非测试：出两张 PNG，用来肉眼验收界面）

run.bat          开游戏 / 跑测试的入口
```

## 三条架构铁律

这三条决定了以后能不能做 AI、撤销、回放、联网：

1. **引擎层绝不 `extends Node`。**
   `engine/` 下全是 `RefCounted`，不碰场景树、不发信号、不读文件。
   一旦把逻辑写进节点，单测、AI 搜索、回放就全做不成了。

2. **随机数必须可注入种子。**
   `Game.new_game(seed)` 之后，同一颗种子必然复现同一副牌。
   回放、撤销、联网同步全靠这一条。

3. **状态变化只走 `do_*` 方法。**
   `do_move` / `do_deploy` / `do_equip` / `do_disband` / `do_play_spell` / `do_discard` / `do_draw` / `end_turn`。
   以后加「动作日志 → 撤销 / 回放」时只需要记录这些调用，不必快照整个状态。

界面的职责因此只有两件：**把状态画出来**、**把点击翻译成 `do_*`**。
网页版 Demo 当初就是这条线没守住才出的 bug —— 那次是点卡 / 点格的链路根本没接上，而引擎测试全绿。
所以这次专门有 `UiSmoke.gd` 盯着这条链路。

## 自对弈跑出来的一个陷阱（重要）

`run.bat selfplay` 让 AI 自己跟自己下了 6 局，撞出一条**规则层面的真实后果**：

> 过河只能走列 3 / 5 / 7 的三座桥，而**小兵过河前不能横走**。
> 所以 —— **部署在列 1 / 2 / 4 / 6 / 8 / 9 的小兵，永远过不了河。**
> 它会一路走到河边卡死，而且**照样占 1 点人口**。

8 点人口里塞几个这种废兵，进攻力量就永远凑不齐了。

第一版 AI 不懂这件事，哪格空就往哪格放，结果：

| AI 版本 | 6 局自对弈结果 |
|---|---|
| 只会「离对方主将越近越好」 | 只 **2 局**分出胜负，其余 4 局卡到 400 回合上限；第 400 回合双方**过河数都是 0**，两军各自堵在河边 |
| 加「优先桥列部署 + 人口满了先解散卡死的兵 + 推进时避开非桥列」 | **6 局全部分出胜负**，平均 113 回合（最快 93，最慢 179） |

结论：**卡死不是规则坏了，是 AI 太笨**；但它顺带证明了这条规则有真实深度 ——
「往哪儿部署」不是随便放的，是这游戏最重的一个决策。
玩家现成的解法有两个：**① 布阵时就把 3 个兵直接放在桥列；② 用「解散」（1 AP）把废兵清掉换回人口。**

如果实测下来觉得这个惩罚太重，可以拧的两个旋钮：
**允许小兵过河前横走**（等于拆掉惩罚），或**放宽部署区**（让它更容易够到桥列）。

## 视觉：水墨淡彩

配色和字体只有**一个来源**：`scenes/Palette.gd`。改颜色改那里，不要在别处写死色值。

**配色纪律 —— 只有两个强调色：**

| 色 | 用途 |
|---|---|
| **朱砂** `#a8322a` | 红方 / 吃子（危险）/ 断桥 |
| **花青** `#3a5a7a` | 选中 / 可选目标（操作）/ 浮桥 |
| 墨分五色（焦·重·中·淡·清） | 其余全部：纸、线、字、辅助标记 |

重构前的毛病是**同时有 6 个互相竞争的强调色**，而且一个 `#c0392b` 身兼三职
（断桥 / 可吃 / 被缚）、一个 `#1f5fa8` 兼两职（浮桥 / 可选目标）。散着写根本看不出来。

**字体两副**：棋子与标题用**楷体**（有笔意），面板小字用**黑体**
（12px 的楷体在屏幕上会糊；小字优先可读性）。

### 棋盘上的 9 种状态，形状 + 颜色双重编码

色弱玩家分不出「可走」和「可吃」如果只差颜色，所以每种状态都有**不同的轮廓**：

| 状态 | 形状 | 颜色 |
|---|---|---|
| 选中 | 粗环 + 四角括号 | 花青 |
| 可走 | 实心小圆点 | 焦墨 |
| 可吃 | 圆环 + 四道短齿 | 朱砂 |
| 可部署 | **虚线**环 | 花青 |
| 死路（过不了河） | 叉 | 中墨 |
| 最近一步 | **方框** | 淡墨 |
| 断桥 | 断头 + 叉 | 朱砂 |
| 浮桥 | 桥面 + 桥板 | 花青 |
| 已装备 | 角上一枚小印，写**装备后的兵种**（马/车/炮） | 本方色 |
| 被绊 | 「缚」字 | 重墨 |
| 空城计 | 细环 | 花青 |

`run.bat shot` 出的第二张图 `_shot_states.png` 就是把这些状态摆在一张盘上，
用来核对它们是否真的分得开 —— 改过任何标记的画法都该看一眼。

## 无头测试测不出来的东西（三条教训）

**一、棋盘底板错位。** `run.bat shot` 抓到的：最下面一行的「士」整个挂在纸外面，
而当时 245 条断言**全绿**。原因是底板宽高算成了网格跨度 `(COLS-1)*CELL`，
漏掉两侧各 `MG` 的留白。

**二、棋子上的字全部偏右半个宽度。** 放大截图才看出来：**圆圈是空的，字挤在圈右边**。
`draw_string(f, pos, s, HORIZONTAL_ALIGNMENT_CENTER, w, ...)` 会从 `pos.x + w/2` 起头。
这个 bug 从最初版本就在，缩放看截图完全看不出来。现在文字一律走 `_draw_centered()`，
并且 `ArchGuard` **禁止** BoardView 里再出现 `HORIZONTAL_ALIGNMENT_CENTER`。

**三、面板区块互相压。** 一段 5 行的长提示盖到了下面的【持续效果】上，
而且效果条目无上限增长，迟早会压到按钮。

### 从这三次里得到的规矩

> **别断言方便断言的，要断言真正拿去用的那个值。**
> 几何断言第一版测的是 `board_size()` 和 `pt()`，而这两个函数从头到尾都正确，等于没测；
> 改成测真正 draw 的 `board_rect()` 才拦得住。

> **一条抓不到 bug 的断言等于没有断言 —— 写完要故意把它弄坏，看它响不响。**
> 排版断言我前后**写错两版**，两版都是绿的、两版都没用：
> ① 用 `get_visible_line_count()` —— 实测它永远等于 `get_line_count()`；
> ② 按「行数 × 行高」自己算 —— 因为 Godot 会把 `Control.size` 撑到不小于内容，
> 所以永远算得过。
> 真相是：**文字不会溢出自己的框，它只会把框撑大去压别人**，
> 所以唯一的判据是「a 的下边缘 vs b 的上边缘」。
> 拿掉 `MAX_EFFECT_LINES` 跑一遍，现在它会报
> `效果区下边缘 349 越过按钮行 280（超出 69）`。

**规矩：改过 `BoardView` / `Main` 的布局，必须跑 `run.bat shot` 肉眼看。**
